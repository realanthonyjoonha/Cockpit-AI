2How sync works, and how you run it

Auto: opening the site with data older than 20h spawns exactly one background run (lockfile mutex + 15-min retry damper — proven with a rewound clock). No cron, ever.

Manual: node cockpit/sync.js · --dry-run (fetches, writes nothing) · --only id,id · --force (ignore per-updater freshness).

Contract, proven live: per-updater try/catch (one death never stops the rest — fault-injection test) · diff-before-write idempotence (a forced re-run changed only genuinely-new headlines) · series append-only · one [sync] line to wiki/log.md per changed run · concurrent run exits code 2.

6The quiz — pass this and we cut over

Answers are under each question (click to reveal). No trick questions — this is the "can I drive it cold" check your spec asked for.

Q1Spot looks stale at 9am. What are the two ways a sync happens, and what stops a double-run?

1) Open the site — if the last run is >20h old it self-freshens in the background. 2) node cockpit/sync.js in the terminal (add --force to ignore per-updater freshness). The lockfile (cockpit/.sync.lock) makes a concurrent run exit immediately; a crashed lock goes stale after 10 minutes.

Q2You want to escalate positioning-unwind to FIRED after an ugly session. What do you touch, and what does the app do?

Edit cockpit/risks/positioning-unwind.md: set status: FIRED, add a dated - 2026-07-XX — [status] … line under ## History. Reload — the register re-sorts (FIRED leads), sigils/chips flip red, the stance strip stays wired. Sync never touches that file; only you do.

Q3Where does the GUARDS banner text on a risk page come from, and which five risks carry the HV badge?

The houseview: frontmatter field — your verbatim house-view line. The five hv: true risks: valuation-rerating (trigger №1) · eng-detours (№2) · memory-per-token (№2's live form + the hinge) · capex-rollover (№3) · etf-tail-sleeve (the expression caveat).

Q4You add a new series CSV. What single file makes it exist for both sync and the site?

cockpit/series/_registry.md — one table row (id · label · unit · source · risk · kind). kind flow renders zero-centered baselines; parked shelves it in Data §3.0. Risks that should chart it list the id in their own series:.

Q5Why can a ₩4T single-day retail net-buy print be REAL, and what guards the series if Naver changes the field's meaning?

Because the field is net shares and Hynix is a ~₩1,765T company — on the 07-02 crash retail absorbed what foreigners/institutions dumped (published print: ₩4,593B; our shares×close: ₩4,386B). Two standing assertions: |net shares| ≤ session volume, and foreigner+institution+individual must net to ≈0 (residual ≤30% of the largest). A breach logs and skips the row — never writes.

Q6What is the ONLY file the system will never write, and what's the one non-cockpit file sync may edit?

house-view.md — never, by anything (name-blocked in every write path, mtime-verified). Sync's single non-cockpit target is wiki/catalysts.md (merge-only date rolls) plus its one-line append to wiki/log.md.

Q7You want a fifth desk for HBM4 qualification tracking. Total code changes required?

Zero. cockpit/desks/hbm4-qual.md with {type: desk, id, name, series: [], topics: [], pages: [], entities: []} + intro prose. It appears in the switcher, filters headlines by its topics, charts its series, renders its pages. (tells: true would add the ⭐ block.)

Q8mu-pe reads 22×. What exactly is that number, and why should you treat it as texture?

Last MU close ÷ trailing-4-quarter diluted EPS from EDGAR (YTD-differenced). It's labeled crude TTM: close-date alignment, no forward estimates, loss quarters gap the series. It instruments trigger №1's direction (multiple expanding while EPS flat) — decision-support texture, not a valuation model.

Q9Sync says "trendforce-spot: ✗ ... — continuing". What happened to the other updaters and the log?

They all ran (per-updater try/catch). If any of them changed something, ONE [sync] line still lands in wiki/log.md and includes failed: trendforce-spot (…). The failure is also in .sync-state.json as lastError; the spot series just doesn't get today's point.

Q10Cutover day: the three commands/changes, and the rollback?

Stop v1 → start v2 with PORT=4680 → rename memory-cockpit → memory-cockpit-v1 and point launch.json's cockpit entry at v2. Rollback = reverse it; the vault needs nothing (v2 never migrated it away from v1 — v1 still reads the same CSVs, minus the new files it ignores). Backup from CP1 sits in ~/Trading/vault-backups/.
