================================================================================
  CHEAT SHEET
================================================================================

  PATH A — no cockpit yet (first full iteration)
  ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
    empty / cold
      → RESEARCH LOOP for ticker #1 until pack verify-green
      → UI-A: build cockpit + first thin desk + smoke
      → END: book + first glass desk

  PATH B — cockpit already running (add company)
  ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
    glass live (e.g. MEMORY | NEBIUS)
      → RESEARCH LOOP for NEW ticker until pack verify-green
      → UI-B: add desk only (no shell rewrite) + smoke
      → END: book + new desk on same cockpit


================================================================================
  DESIGN LAW
================================================================================

  Research reliability = specs + formats + compile/verify loop (fail-closed).
  UI reliability       = thin-desk contract + smoke; two playbooks (A vs B).
  Thin-desk chrome parity = plans/2026-07-21-thin-desk-ui-reliability-loop.md
  House CONFIRM / risk ACCEPT stay human.
  Full project iteration always delivers a cockpit; start state chooses UI-A or UI-B.
